# Архитектура

[English](../en/ARCHITECTURE.md) · **Русский**

## Границы модулей

Это генератор SVG с адаптером публикации в GitHub, а не постоянно работающий игровой сервер. Для такого размера подходят обычные функции и явные структуры данных. Контейнер зависимостей, фреймворк и база данных не нужны.

| Слой          | Ответственность                            | Допустимые зависимости              |
| ------------- | ------------------------------------------ | ----------------------------------- |
| `domain`      | Карта по seed, движение, пересечения, цели | Только модули domain; без Node I/O  |
| `calendar`    | Проверка данных и получение календаря      | Свои модули и API платформы         |
| `art`         | Чтение атласов, материалы и сцены          | Константы domain и модули графики   |
| `render`      | Календарь, персонаж, эффекты, сборка SVG   | Domain, calendar, art и render      |
| `publication` | Выбор дня, проверка состояния, сохранение  | Вычисления, рендер и адаптер GitHub |
| `scripts`     | Аргументы CLI, файлы, окружение, запуск    | Рабочие модули src                  |

Архитектурная проверка запрещает циклы статических импортов, I/O в domain и обратные зависимости из src на CLI, сайт и тесты. Это полезное ограничение, а не доказательство отсутствия любых динамических зависимостей.

## Поток данных

Недели календаря → проверенная сетка → воспроизводимая карта → сегменты движения и события выстрелов → SVG → проверенная пара SVG/state → один коммит `output`. Сеть изолирована в `calendar/github-client.mjs`, запись в GitHub — в `publication/output-store.mjs`.

Координатор миссии владеет живыми целями и генератором псевдослучайных чисел. Построитель движения владеет временем и позицией бойца. Состояния замкнуты внутри одной миссии. Порядок вызовов RNG и округление входят в контракт: перенос случайного вызова меняет хореографию даже при корректных типах данных.

Рендер разделён по задачам: `calendar-grid.mjs`, `player.mjs`, `effects.mjs`, `shot-pool.mjs`, затем `render-svg.mjs`. Модули графики описывают сцены; размеры коллизий находятся в конфигурации domain. Импортировать domain можно без чтения графических файлов с диска.

## Стабильный внешний вид

Все четыре официальные локации: 1200×469, viewBox `0 -32 1200 469`, клетки 18px с шагом 20, начало поля (72,60). Ник: monospace bold 21px, базовая линия -8. Месяцы: monospace bold 15px, базовая линия 46. Палитры различаются, отдельное масштабирование одной сцены не допускается.

Оптимизированные векторные контуры и пулы эффектов из 2.8.1 сохранены. Элемент используется повторно только после исчезновения предыдущих эффектов. Исходные атласы сохранены рядом с воспроизводимыми оптимизированными. Рефакторинг проверяется по SHA-256 эталонных SVG версии 2.8.1 и снимкам Chromium/WebKit. Эмуляция не измеряет FPS на настоящем iPhone.

## Осознанные компромиссы

`createMission` остаётся координатором с состоянием: порядок его действий имеет значение. Дробить его на десятки абстракций ради количества файлов не нужно. Экспериментальные локации сохранены для проверок, но исключены из публикации. Поддерживаемый интерфейс — workflow и документированный CLI; внутренние пути src не являются стабильным API библиотеки.

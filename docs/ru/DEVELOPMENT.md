# Разработка

[English](../en/DEVELOPMENT.md) · **Русский**

Используйте актуальный патч Node.js 22 LTS или новее. Пользователям анимации Node, npm и форк не нужны; эти действия предназначены разработчикам.

1. Склонируйте репозиторий и создайте короткоживущую ветку.
2. Выполните `npm ci`: установятся закреплённые инструменты разработки. У рабочего генератора нет npm-зависимостей.
3. Выполните `npm run check`, `npm run lint`, `npm run format:check` и `npm test`.
4. Выполните `npm run demo` и откройте `generated/commando-activity.svg` в браузере. Тестовые данные явно помечены; публиковать их как реальные запрещено проверками.
5. Создайте PR. До релиза CI проверит вычисления и браузерную отрисовку.

Для единого оформления используйте `npm run format`. Комментарии должны объяснять геометрию, границы безопасности и неочевидные инварианты, а не пересказывать обычные команды. В domain не должно быть сети и файлового I/O. Подробнее — [архитектура](ARCHITECTURE.md).

## Изменение графики

Оригиналы — `assets/*-sprites.json.gz.b64`. После согласованной правки выполните `node scripts/compile-pixel-art.mjs` и сохраните соответствующие `*-optimized.json.gz.b64`. Команда `npm run check:art` проверяет воспроизводимость. Не редактируйте оптимизированные данные вручную и не меняйте палитру ради прохождения ограничения размера. Сначала прочитайте [условия ресурсов](../../ASSET_RIGHTS.ru.md).

## Проверка внешнего вида

CI получает отдельный эталон v2.8.1 и сравнивает четыре локации в Chromium и WebKit при 1200px/1× и 390px/3×: выстрелы, попадания, прыжки и восстановление. Для повторения после установки браузеров Playwright выполните `node tools/verify-rendering.cjs PATH_TO_REFERENCE generated/visual-check`. `BROWSER_ENGINE=webkit` выбирает WebKit. Допускаются небольшие округления растеризатора; точный SVG-контракт отдельно защищает результат на корректных тестовых календарях.

Обратная связь с реального телефона всё равно нужна. Проверка headless-браузера не означает измерение FPS на iPhone.

## Выпуск версий

Смотрите [правила релизов](RELEASING.md). Не перемещайте существующие стабильные теги. Храните завершённую работу в истории PR и тегах, а не в постоянных ветках отдельных сцен. [История переноса](MIGRATION.md) объясняет разделение игры и профиля.

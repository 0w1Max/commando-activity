# Справочник

[English](../en/REFERENCE.md) · **Русский**

## Поддерживаемый сценарий

Личный публичный репозиторий GitHub-профиля (`LOGIN/LOGIN`), classic PAT владельца со scope read:user и GitHub Actions. Организационные профили и fine-grained PAT не проверены. Данные читаются через GitHub GraphQL; результат — готовая SVG-анимация, не интерактивная браузерная игра.

## Команды

| Команда                                                | Результат                                            |
| ------------------------------------------------------ | ---------------------------------------------------- |
| `npm run demo`                                         | Помеченные тестовые SVG и состояние в generated/     |
| `node scripts/generate.mjs --demo --output PATH`       | Отдельный тестовый SVG                               |
| `node scripts/generate.mjs --output PATH`              | Реальный SVG; нужны данные доступа владельца         |
| `node scripts/publish-daily.mjs --previous-state PATH` | Дневная публикация; для live нужен предыдущий state  |
| `node scripts/validate-daily.mjs SVG STATE`            | Проверка реального результата по настройкам          |
| `node scripts/compile-pixel-art.mjs --check`           | Проверка оптимизированных атласов по исходникам      |
| `npm test`                                             | Регрессионные тесты и точный SVG-контракт            |
| `npm run check`                                        | Границы модулей, циклы, версии и ссылки документации |

## Входные данные

| Название                    | Назначение                                                            |
| --------------------------- | --------------------------------------------------------------------- |
| `GITHUB_USER`               | Логин владельца; workflow берёт его из вызывающего репозитория        |
| `GH_TOKEN` / `GITHUB_TOKEN` | Токен владельца для CLI; не сохраняйте его в файлы и URL              |
| `COMMANDO_READ_USER_TOKEN`  | Имя секрета профиля, передаваемого как read_user_token                |
| `COMMANDO_MAP_SEED`         | Повторение произвольной CLI-карты; не меняет seeds дневной публикации |
| `COMMANDO_LOCATION`         | Локация для отдельного CLI-запуска; daily использует настройки        |
| `commando-settings.json`    | Версия, seeds официальных локаций и ротация Europe/Moscow             |

Дневной workflow передаёт PAT только шагу генерации календаря. Отдельный автоматический GITHUB_TOKEN записывает результат. Для работы не нужны npm-зависимости, сервер и база данных.

## Результат и обновление

`output/commando-activity.svg` и `output/commando-state.json` сохраняются вместе. В JSON — схема/версия, дата/локация/seed, предыдущий выбор, сведения о календаре и SHA-256 картинки. Это согласованная пара; отдельно файлы не редактируйте.

Пример запускается в 21:17 и 09:17 UTC (00:17 и 12:17 Москвы). GitHub может задержать запуск, а картинку — закешировать. В тот же московский день сохраняются локация и seed, но новая активность меняет миссию. Следующий опубликованный день не повторяет предыдущую локацию, даже после пропуска запусков.

# Политика безопасности

[English](SECURITY.md) · **Русский**

Поддерживаемый эталон — последний стабильный релиз. Старые закреплённые версии остаются доступны, но автоматический backport исправлений не гарантируется. Изучайте описание и устанавливайте совместимые patch-релизы.

## Как сообщить о проблеме

Приватные сообщения об уязвимостях включены: это подтверждено скриншотом GitHub от владельца 27 ноября 2026 года. Откройте [Security → Advisories](https://github.com/0w1Max/commando-activity/security/advisories) и используйте **Report a vulnerability** для приватного сообщения. Если позднее кнопка станет недоступна, создайте Issue с просьбой о приватном канале связи без подробностей эксплуатации и данных доступа. Не публикуйте PAT, приватный экспорт календаря и непроверенные логи.

## Границы доверия

- Помощник готовит ссылки/фрагменты локально и не запрашивает токен. В браузере сохраняется только выбранный язык.
- PAT владельца находится в секрете репозитория и передаётся только генерации календаря. Используйте минимальный read:user и срок действия; write/admin-права не нужны.
- Отдельный GITHUB_TOKEN записывает SVG/state вместе. Тот, кто меняет доверенный код workflow, потенциально может использовать его данные доступа; ограничивайте права записи в репозиторий.
- Сторонние Actions закреплены проверенными SHA коммитов. Релизный тег — удобное закрепление, но не криптографическая защита от компрометации аккаунта сопровождающего.
- Проверки SVG обеспечивают контракт собственного генератора. Это не универсальный санитайзер произвольных загруженных SVG.

PR-проверки не получают production-секреты. Запись релизов выполняется после проверок основной ветки. Аудит зависимостей и тесты снижают риск, но не являются пентестом и не гарантируют отсутствие любых уязвимостей. Административные настройки отделены от проверок исходников; ниже зафиксировано датированное проверенное состояние.

## Настройки репозиториев

Включены правила защиты `main` и релизных тегов `v*`. Для `main` обязательны pull request и успешные проверки `test` и `visual` от GitHub Actions; требуется актуальная база и закрытые обсуждения ревью. Удаление и принудительная перезапись `main` запрещены. Изменение и удаление существующих релизных тегов запрещены; создание новых разрешено. Обязательных одобрений второго участника нет. Списки обхода правил пусты.

Настройки rulesets проверены через API GitHub 27 ноября 2026 года. Скриншоты GitHub, предоставленные владельцем в тот же день, подтверждают включённые Secret Protection, Push protection и Private vulnerability reporting в `0w1Max/commando-activity`. Secret scanning показывает **0 открытых уведомлений** в репозиториях игры и профиля. Это датированное наблюдение за уведомлениями, не доказательство отсутствия любых возможных секретов.

Репозиторий профиля `0w1Max/0w1Max` описывается отдельно: его список rulesets пуст, правила веток профиля в рамках этой работы не включались. Скриншот профиля подтверждает 0 открытых уведомлений Secret scanning; переключатели Secret Protection, Push protection и приватных сообщений для профиля отдельно не проверены.

См. [проверенные настройки и сопровождение](docs/ru/REPOSITORY_SECURITY.md). JSON-заготовки остаются выключенными примерами; это не действующие rulesets.
